# 项目总览 1.0

从项目的总览 MD、地图 MD 和批准段引用的决策卡，生成一页项目总览（HTML）：标题区与“现在要你定的事”横幅，两个标签“功能与架构”（完成情况、五段分组的功能清单、技术架构）和“每轮决策”（时间线、每轮定了什么、为什么这样定）。页面样式和交互是 2026-10-29 的定稿；事实只在 MD 和卡里，页面是生成的阅读副本。

- Agent 怎么用：[SKILL.md](SKILL.md)。
- 写法：共享规程 03 的[“总览 MD 头字段与分组”](../../协作规则/03-项目规则模板.md#overview-md)、[“地图 MD 头字段与批准段”](../../协作规则/03-项目规则模板.md#decision-map-header)、[“决策卡写法”](../../协作规则/03-项目规则模板.md#decision-card)。
- 样本：[examples/总览-示例.html](examples/总览-示例.html)，由虚构项目 `examples/示例项目/` 生成。

## 运行

Node 18 及以上，不装任何依赖：

```sh
node scripts/overview.mjs --source <项目根> --output <项目根>/项目总览/html/总览.html
```

- **写**：只写 `--output` 这一个文件，同名覆盖；输出目录要已存在。页面不加载任何外部字体、脚本、样式，双击即可打开；页面里没有生成时间，同样的 MD 生成的页面一字不差。
- **只查不写**：`node scripts/overview.mjs --check <项目根>` 读和校验同上，报同样的问题清单，没问题时打印同样的计数和提示；不写任何文件，退出码同正常运行。
- **终端**：成功时打印输出路径、功能各状态项数与组数、读到的轮次和要你定的事件数，以及“提示”行。不合格时按文件列出全部问题、退出码 1、不写页面，提示行照样列在后面。

## 读什么

| 读 | 取什么 | 上页面哪里 |
|---|---|---|
| `项目总览/md/总览.md` 的一级标题 | 去掉“功能与架构总览”后的项目名 | 页面标题“项目名 项目总览” |
| 头字段“现状”“核对” | 一句现状；核对日期 | 标题下粗体一句；元信息行 |
| 一级标题与“## 功能清单”之间的段落 | 介绍段；以“状态只有五种”起头的一段不上页面 | 标题下小号灰字 |
| “## 功能清单”的“### 段名：组名”和三栏表格 | 功能、状态（五个写法）、第三栏去掉 HTML 注释作备注 | 完成情况（计数由生成器算）、功能清单 |
| “## 技术架构”的四栏表格和表后段落 | 部分、管什么、用的技术、像建筑里的；串讲段 | 技术架构卡、串讲框 |
| `项目总览/md/决策地图.md` 头字段“要用户决定” | 每件一行，缩进的子项：以“推荐”“何时之前”“不定会挡住”起头的各归一类，其余算选项；写“无”就没有 | 横幅 |
| 批准段 `## 第 N 轮 · YYYY-MM-DD · 主题` | 四个清单和“接下来”；“定了要做”每条行尾的“｜ 进度：已完成／进行中／待完成” | 每轮决策（最新在上，默认显示最新一轮） |
| 批准段行尾注释 `<!-- NN 卡 -->`、`<!-- NN 卡；票 NN -->` | 在 `专题工作/*/决策卡/NN-*.md` 找卡：H1 去掉“决定：”作格标题，`## 给你的三句话` 整节（单独一行“无”不上页面），加“选择与理由”里以“为什么更好：”起头的一行 | 本轮“为什么这样定”，一张卡一轮一格 |

“轮次”“本轮范围”“下一步”三个头字段只核对有没有写，页面不显示：每轮的“接下来”取自批准段。旧的“上一轮简报”标签认得、不用。总览 MD 里的“## 完成情况”和其他二级标题不读，打提示。

## 报错停止的情况

- **找不到文件**：没有 `总览.md`（同目录有 `功能地图.md` 时提示改名）或 `决策地图.md`。
- **总览 MD 头部**：一级标题不是“<项目名> 功能与架构总览”；缺“现状”“核对”或没内容、写了两次、用了半角冒号；核对不是 YYYY-MM-DD；现状超过 40 字。
- **分组**：组标题不是“段名：组名”；段名不在进入、使用、管理、维护、后台五个里；段的顺序不对；一组不在 4 到 12 项；全部超过 10 组；同一句功能出现两次。缺“功能清单”或“技术架构”一节，或节里没读到内容。
- **状态**：功能行不是三栏、功能一栏空、状态不是 ✅、进行中、待完成、未定、不做之一；功能行前面没有组标题。
- **正文里的编号**（去掉注释后扫）：`Spec` 加编号、一个大写字母加两位数字（T05、B58、A41）、`票 06`、`33 卡`、`ADR`、`v1.7`、`0.1.28` 这类。扫的范围：现状、介绍段、组名、功能与备注、技术架构与串讲段，批准段的主题、各清单和“接下来”。一段正文里几处编号各报一条；“门票、车票、发票”这类词后面跟数字不算票号。
- **地图 MD**：缺“轮次”“本轮范围”“要用户决定”“下一步”之一或没内容、写了两次、用了半角冒号。
- **批准段标题**：像新写法（“第 N 轮”后跟“·”）却读不出，比如漏了一个“·”；日期不是有效日期。这种不当旧写法放过。
- **新写法批准段**：缺四个清单之一（没内容要写“无”）或缺“接下来”；清单写了两次；“定了要做”某条没写进度或进度不是三个写法之一；主题超过 25 字；同一轮写了两段。
- **卡引用**：引用的卡号在 `专题工作/*/决策卡/` 下找不到，或同号有两张以上；引用到的卡没有一级标题。

字数一律去掉空白后按字符数算，中英文和标点各算一个（“从 Admin 进后台”算 9 字）。

## 终端提示的情况

不挡出页，成功和报错时都列出：

- 地图 MD 里每一段旧写法的批准段（标题像“第 N 轮…”、“轮”后面没有“·”），一轮一行，没有读。
- 批准段“定了要做”“定了不做 / 以后再说”某条行尾没有卡引用。
- 批准段引用的卡没有“给你的三句话”，这一格不出；有三句话、没有“为什么更好：”一行，这一格只有三句话。
- 组名超过 9 字，页面上可能折行。
- “要用户决定”某件缺选项、推荐、何时之前、不定会挡住什么之一。
- 功能不是 ✅，第三栏是空的。
- 总览 MD 有“完成情况”一节或其他认不得的二级标题；介绍段有“状态只有五种……”一段；“功能清单”里有表格和组标题以外的文字。

## 安装为技能

安装要用户当次同意。目录链接（本机做法）：Claude Code 建 `~/.claude/skills/project-overview`，Codex 建 `~/.agents/skills/project-overview`，都指向本目录。macOS：

```sh
ln -s "<仓库>/工具/项目总览" ~/.claude/skills/project-overview
```

Windows 用 PowerShell 7：`New-Item -ItemType Junction -Path "$HOME\.claude\skills\project-overview" -Target "<仓库>\工具\项目总览"`。也可以把 `SKILL.md`、`README.md` 和 `scripts/` 复制过去。Claude Code 只认 `~/.claude/skills` 和项目的 `.claude/skills`；装好后在对话里要“出项目总览”或输入 `/project-overview`。

## 测试与样本

在本目录运行 `node --test`。测试把 `examples/` 复制到系统临时目录再改，不写本目录；在 Node v24 上跑过。改了生成器或样本之后重新生成入库的样本页，否则“样本生成幂等”那条测试会失败：

```sh
node scripts/overview.mjs --source examples/示例项目 --output examples/总览-示例.html
```

`examples/示例项目/` 是虚构的“河畔书屋借阅小程序”：总览 MD 五段六组 27 项、五种状态都有；地图 MD 四个头字段，“要用户决定”一件五要素齐；第 1 轮是旧写法（出提示），第 2、3 轮是新写法，第 2 轮有一条没写卡引用（出提示）；六张卡里三张有“给你的三句话”和“为什么更好：”，两张被引用却没有（出提示），一张未定卡没被引用。

## 已知限制

- **编号扫描靠样式猜**：一个大写字母加两位数字的产品名（如 X86）会被当成票号；`A1`、`R1` 这种一位数字的需求编号扫不到；“门票”等例外词之外，别的“某票 20”也会被当成票号。
- **“要用户决定”按子项开头的词归类**：一行里同时写“何时之前”和“不定会挡住”只算前一个，另一个会被提示缺。
- **Markdown 只认用到的写法**：表格、段落、列表、粗体、行内代码和链接（链接只留文字）。总览 MD 的注释可以跨行；批准段的卡引用注释要写在本条同一行。代码块、图片不支持。
- **只测过 Node v24 和 macOS**。脚本只用 Node 18 已有的接口，Windows 和 Node 18 没有实机跑过。
