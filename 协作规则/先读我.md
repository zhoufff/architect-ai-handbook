# 先读我：这套协作规则怎么用

这里是《建筑师的 AI 开发手册》配套的协作规则，给用 Claude Code 或 Codex 做开发的同事。手册讲为什么这样做，规则规定 AI 具体怎样选路线、开工、交接和验收。它是作者和小团队的协作选择，不是 Anthropic、OpenAI 或 Matt Pocock 的官方流程；采用前先和团队确认。

## 六份文件

| 文件 | 管什么 | 怎么用 |
|---|---|---|
| [01 全局准则模板](01-全局准则-模板.md) | 个人准则：硬停、沟通、推进、模型偏好、路由表 | 复制成自己工具的全局文件，填好占位符 |
| [02 通用开发规程](02-通用开发规程.md) | 路线、建档、四阶段、关口、会话与派工、验证、Skill、施工日志与决策简报 | 不复制，AI 按 01 的路由表在需要时来读 |
| [03 项目规则模板](03-项目规则模板.md) | 项目根 AGENTS.md 的模板，含资料目录和决策卡写法 | 建新项目或调整项目规则时 |
| [04 Agent 角色说明](04-Agent角色说明.md) | 主控、建图、施工、审查、决策问答等九个角色各自读什么、写什么、交回什么 | 派工或接手角色时 |
| [05 任务开工包模板](05-任务开工包模板.md) | 新开会话时贴的第一条消息；决策问答单用三行 | 派工时 |
| [06 规则维护与启用检查](06-规则维护与启用检查.md) | 维护规则、接入工具、检验启用 | 维护或核对时 |

## 接入五步

1. 把本目录放到自己电脑上一个固定位置（比如克隆整个仓库），记下它的绝对路径。
2. 复制 `01-全局准则-模板.md` 为工具的全局文件：Claude Code 是 `~/.claude/CLAUDE.md`，Codex 是 `~/.codex/AGENTS.md`。已有全局文件的，先备份再合并，不要直接覆盖。
3. 填占位符：第 1 节身份与语言、第 5 节模型表、第 6 节系统与工具；第 6 节路由表的链接改成第 1 步那个目录下的绝对路径。第 0、2、3、4 节可以原样用，也可以按自己的习惯改。
4. 02 到 06 不复制，留在原目录；AI 在触发时按路由表去读。
5. 新开一个会话核对：问它“硬停有哪几条”“施工日志六项是什么”，答得上来才算接好。已经开着的会话不会重新加载全局文件。

项目接入：项目根目录的 `AGENTS.md` 按 03 填；Claude Code 需要时在项目 `CLAUDE.md` 里写一行 `@AGENTS.md` 引入同一份，不复制正文。

## 需要知道的限制

- 体量：Codex 把全局和项目各层 AGENTS.md 拼接后只读前 32 KiB，超出部分静默丢弃；Claude Code 建议每份 CLAUDE.md 不超过 200 行。全局文件加项目 AGENTS 合计保持在 32 KiB 以内。数值按 2026-09-16 的官方文档。
- 自动记忆：Claude Code 默认开，存在 `~/.claude/projects/<项目>/memory/`；Codex 默认关。它们只作回忆，不算记录，也不跨电脑；必须生效的偏好写进项目 AGENTS 的“偏好与不再问的事”或全局文件。
- 更新：规则会随手册更新，拉取本仓库最新版即可，02 到 06 不必另外同步；01 模板的变化由你决定是否并入自己的全局文件。
- 02 第 5 节技能表里的 `decision-brief` 链到本仓库的 [工具/决策简报](../工具/决策简报/)，按它的 README 安装；架构图用上游 Archify，安装命令见仓库 [README](../README.md)。
