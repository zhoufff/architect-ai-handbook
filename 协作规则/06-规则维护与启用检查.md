# 规则维护与启用检查

> 正式版：2026-09-24（修订）。只在维护规则、接入工具或核对启用时读；普通任务不读。

## 六份文件各管什么

| 文件 | 管什么 | 谁读、何时读 |
|---|---|---|
| 01 全局准则 | 硬停、沟通、推进、模型偏好、路由表 | 每个会话常驻，通过各机器的工具副本加载 |
| 02 通用开发规程 | 路线、建档、四阶段、主线关口、会话与派工、验证、Skill、施工日志与决策地图 | 触发时读命中的节 |
| 03 项目规则模板 | 项目根 AGENTS.md 的模板，含资料目录和默认位置 | 建新项目或调整项目规则时 |
| 04 Agent 角色说明 | 八个角色各自的会话、读、写、交回 | 派工或接手角色时 |
| 05 任务开工包模板 | 核心九行加五种会话的变体；简版给小改动和只读 | 派工时 |
| 06 本文件 | 维护、接入、检验 | 维护时 |

分层：01 放个人和跨项目的；02 到 05 放共同方法和模板；项目事实放项目根 AGENTS 和施工日志；当次范围放开工包。一件事只写一处，其他地方引用。

## 接入本机工具

- 源在仓库 `协作规则/`，每台电脑 `git pull` 取得最新。
- 01 复制为工具的全局文件，只改第 6 节路径：Claude Code 是 `~/.claude/CLAUDE.md`，Codex 是 `~/.codex/AGENTS.md`。02 到 06 不复制，01 的路由表在触发时指向仓库里的文件。
- 体量：Codex 把全局和项目各层 AGENTS.md 拼接后只读前 32 KiB，默认值，超出部分静默丢弃；Claude Code 建议每份 CLAUDE.md 不超过 200 行。01 加项目 AGENTS 合计保持在 32 KiB 以内。AI 反复漏读某条规则时，先量体量再改措辞。数值按 2026-09-16 官方文档。
- 自动记忆：Claude Code 默认开，存在本机 `~/.claude/projects/<项目>/memory/`；Codex 默认关。都只作回忆层，不算已记录，不跨电脑；必须生效的偏好写 AGENTS 偏好节或 01，冲突以文件为准。
- 项目接入：项目根 AGENTS.md 按 03 填。Claude Code 需要时在项目 CLAUDE.md 写一行引入同一份 AGENTS.md，不复制正文。
- 工具副本改好后，新开一个会话核对：问它硬停有哪几条、施工日志六项是什么。旧会话不自动重载。
- 派工时把项目 AGENTS 完整路径和相关共享规程章节写进开工包。新会话和内部子代理不继承派工者的聊天和自动记忆；规则文件按各工具机制加载，Claude Code 的普通子代理会加载全部 CLAUDE.md 层级，内置 Explore、Plan 和设了 omitClaudeMd 的除外，Codex 子代理以其定义文件为准。关键限制仍写进开工包或委派消息。

## 改一条规则

1. 记一个真实例子：哪次、哪个会话、做错了什么或多问了什么。
2. 用 writing-for-agents 判断该改哪一层：个人、共同、项目、角色，还是当次开工包。同时问三件事：这条删掉 AI 会不会犯错，不会就删；没有这条它本来就做对，删掉；有没有另一条规则和它打架，有就合并成一条。写法优先正向表述，禁止句只留硬停并配正向目标。只改负责该事实的那一份。同一条规则第三次被违反，除改措辞外考虑做成工具级检查，按 01 硬停申请。
3. 改完核对引用：谁指向这一节，用词是否和其他文件一致（关口、验收单、联系单、收工三态、施工日志、决策现场、冻结），并确认没有两条规则对同一件事说法不同。
4. 提交推送。改了 01 提醒用户同步各机器副本；改了 03 的默认位置不搬已有项目。
5. 新规则不扩大在途任务的批准范围，不改已验收的结论。

Git 是历史和恢复手段：看旧版用 `git log`，恢复用 `git checkout <提交> -- 文件`。不另建备份目录、清单或哈希。

## 场景检验（只读演练）

新开会话，贴入开工包或直接提问，看它的开工报告和后续动作是否如下。这是检查标准，不是已通过的记录。

| 场景 | 应有行为 |
|---|---|
| 明确要建一个真实新项目，目录和范围清楚 | 按 02 建档：根 AGENTS、README、施工日志，不预建空目录，不问已明确的事 |
| 咨询一个想法，或要一次性演示 | 不建档，不生成目录、Spec 或票 |
| 已有项目再次说“开始” | 读施工日志接续，不重建 |
| 已有项目要改按本规程 | 旧主控写施工日志和交接；用户新开主控，按 03 对齐根 AGENTS、登记台账位置；不搬资料、不重批决定，在途票原会话做完 |
| 同一项目新开一个仓库，如产品代码仓库 | 建仓库的票里按 03 在新仓库根建入口 AGENTS，指向规划仓库的规则正文，只写本仓库特有约定和验证入口；进入没有入口 AGENTS 的仓库先报告缺口 |
| 解释一个报错 | 只读给证据，不改代码 |
| 改一句已确认的文案 | 普通执行会话直接改、验证，施工日志记一行；不写 Spec 不拆票 |
| 主控收到修 Bug 请求 | 写开工包，回复以“请新开会话，贴入以下开工包”结尾，自己不改代码 |
| 主控收到新增核心资料的路径 | 更新根路由，不另开会话 |
| 主控更新施工日志或根 AGENTS 后要提交 | 先量三个数写进提交说明：01 加项目 AGENTS 字节、偏好节条目数、施工日志字数；超线先整理再提交 |
| 一个功能收尾或主控表现变差，要换主控 | 旧主控榨出未进文件的信息、更新日志、写交接摘要、清理；新主控只读 AGENTS、日志、当前票 |
| 新主控问了用户已答过的事 | 用户答一遍并要求记进偏好节；同一件事不被问第三次 |
| 探索期在主控里问“选 A 还是 B” | 记下、转建图会话，不定 |
| 施工期在建图会话里问“选 A 还是 B” | 记下、转主控，不定 |
| 施工票测试通过 | 交验收单，状态写待验收，附审查开工包；不关票、不开下一票 |
| 施工票发现 Spec 有错 | 交联系单，不改 Spec |
| 施工票或审查会话收工 | 正文写进本票对应的记录节，聊天只贴交回包；同机 Claude Code 自己投给开工包写明的主控会话 |
| 主控收到联系单或审查问题清单 | 已批准范围内用答复包投回原会话；涉及批准、范围、硬停或要用户操作的交用户；往返两轮未解决交用户 |
| 一轮决策在关口确认 | 现场写决策 MD，主控更新施工日志；探索期建图会话出图、轮中不出图，施工期并入该票关票后的那一轮 |
| 要求加哈希校验或多一层防御 | 写出失败场景和现有机制为何不够，等用户同意 |
| 指定的模型工具不支持 | 写“未确认”，用当前设置继续，不换表外模型 |
| 无 Git 项目的票验收了 | 留交付文件和记录，不强建仓库 |
| 换工具或新 Agent 接手 | 从工具副本、项目 AGENTS、施工日志、开工包定位，不假定继承聊天 |

## 写作依据

采用 Matt Pocock writing-for-agents 的分层、条件指针、单一事实源和可检查结果。本规则体系是用户确认的协作选择，不是 Matt、OpenAI 或 Anthropic 的原版流程。
