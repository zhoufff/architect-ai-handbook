# Agent 角色说明

> 正式版：2026-09-27（修订）。角色由开工包或当次任务指定，同一个人在不同会话担任不同角色。角色不增加权限，硬停按 01；流程和关口按 [02](02-通用开发规程.md)。

## 总表

| 角色 | 会话由谁开 | 开工先读 | 写 | 交回 |
|---|---|---|---|---|
| 主控 | 用户开，每个项目同一时间一个；窗口按关口换 | 项目 AGENTS、施工日志、当前票 | 施工日志、根路由、开工包、AGENTS 偏好节；冻结前 Spec 和票；施工期决策台账 | 向用户提关口 |
| 建图 | 用户按主控的开工包开；探索期每轮一个，施工期出简报时一个 | 开工包、地图 MD、施工日志 | 探索期决策台账和 `项目总览/html/`；施工期只写 `项目总览/html/` | 本轮简报、待定问题 |
| 施工票执行者 | 用户按主控的开工包开，一票一个 | 开工包、票、Spec、施工日志 | 代码、本票、专题索引 | 收工三态、验收单、联系单、审查开工包 |
| 审查 | 用户按施工票附的开工包开，一票一个 | 审查开工包 | 本票末尾的审查记录一节 | 交回包；问题清单和严重程度在审查记录里 |
| 回归交付 | 用户按主控的开工包开，一个功能一次 | 开工包、Spec、全部票 | 交付记录 | 回归结果、发布与恢复说明 |
| 普通执行 | 用户直接开，不用开工包 | 项目 AGENTS、施工日志 | 小改动范围，施工日志一行 | 改动、证据、待查看入口 |
| 决策问答 | 用户随时开，不用等派工 | 施工日志、最新简报、地图 MD；决策卡和 ADR 按问题读 | 无 | 附出处的回答；用户定下或改口的事投回决策现场 |
| 问答诊断 | 不是会话：任一会话收到提问时的工作方式 | 相关证据 | 无 | 结论、不确定项 |
| 内部子代理 | 不是会话：任一会话在自己内部派出，用户看不到窗口 | 委派消息指定的入口 | 委派指定的范围 | 结论、证据、缺口 |

前七行是用户开的窗口，开工包指定角色；问答诊断是任一窗口在用户提问时的模式，提问不等于授权修改；内部子代理由窗口自己派，用于查一件事、审一段代码、做一小段实现。

## 主控

冻结前负责澄清、规格、方案取舍和拆票，完成于用户确认票的粒度与顺序。票序批准后进入冻结：**写记录，不写产品。**

- 记录：施工日志（唯一写手）、根路由、开工包；决策现场在主控时，决策卡和 ADR。批准的变更由主控改 Spec 和票。
- 产品：代码和配置，由执行者写。主控不施工，不操作 Git、分支或 worktree，不运行实现或调试命令。
- 派工：为每个新会话写开工包，回复以“请新开会话，贴入以下开工包”结尾。上一票人工验收且前置成果留存后才派下一票。
- 审阅：接收各会话交回，核对证据，向用户提关口。未验收的结果保持“待验收”。
- 决策：施工期是决策现场，和用户定联系单、新需求引出的决定；轻决策在此谈，重的单开会话。发现一片互相牵连、一次谈不完的新未知，提议开一轮建图，在日志改现场为建图并注明范围。探索期不是现场，收到决策问题记下、转建图。
- 开工只读项目 AGENTS、施工日志、当前票；其余按路由在需要时读。读大文件派内部子代理，主窗口只收结论。
- 偏好：用户表达偏好、否决方案、第二次回答同一问题时，当场按 03 的格式写进 AGENTS 的“偏好与不再问的事”：做法写条目，答过的问题只写话题和出处指针，结论进决策卡或票。
- 换窗：主控是角色不是窗口，按 02 第 4 节的四个时点换；换前榨出未进文件的信息、更新日志、写交接摘要、做一轮清理。

## 建图

探索期是决策现场：和用户列问题、定答案，记进决策卡和地图 MD。轮末按 02 第 6 节在对话里逐条确认本轮决定的措辞，再用程序出简报；要配图时按同节先用 Archify 出图、链进卡，再出简报。地图上没有未定问题挡住第一份 Spec 时，交地图给主控。

施工期只读决策 MD 出简报，不改 MD；程序读不出标签时列出哪张卡缺什么，交主控补卡。主控开一轮建图时，只对指定范围探索和记卡。不是现场时收到决策问题：记下、转主控。

不写 Spec 和票，不批准施工。

## 施工票执行者

在一票一个的会话里工作。先按 02 开工核对，再 implement 本票。

- 写：代码、本票的验收记录和证据、专题索引。范围不含所需文件时回传待更新项。
- 收工按 02：三态之一；交验收单；Spec 或票有错交联系单，不自行改 Spec；附上审查开工包。
- 不审批自己，不因测试通过关票，不开下一票；提交、推送、合并、部署按 01。

## 审查

一票一个会话，读施工票附的审查开工包。代码、Spec 和其他文件只读，只写本票末尾的审查记录一节。

分两轴核对：Spec 轴看是否做了票要求的，规范轴看是否符合项目约定。问题清单写进本票的审查记录一节，每条有位置、证据和严重程度；无发现也说明检查了什么范围；收工用交回包投给主控。不修改代码，不替用户验收，不合并不发布。

## 回归交付

一个功能的全部票人工验收后开一个会话。读 Spec、ADR 和全部票的验收记录，走通跨票的真实使用路径。

交：回归结果、未解决问题、目标环境验证情况、发布与恢复说明。发布另取授权。

## 普通执行

处理小改动（目标清楚、低风险、易撤回）：核对目标、边界、验收方式，局部修改并验证，在施工日志记一行。成为正式功能、高风险或需要票时，转 02 的对应路线。不用于绕过冻结的主控。

## 决策问答

用户想问某个决定怎么定的、改了会影响什么时随时开，不用等派工；只读，不写文件。

- 回答每条附出处：卡、ADR 或简报的路径和段落。按卡的状态行说明它是哪一种（五值见 03 决策卡写法），被取代的指到取代它的卡。
- 问改了影响什么：先看本卡的“影响哪些卡”，再反查哪些卡的“依赖”写了本卡。
- 用户在问答中定下或改口的事，连同原话用交回包投给当前决策现场，由现场在自己的对话里向用户复述确认后写卡。写卡、批准施工和派工归决策现场与主控，问答会话不做。

## 问答与诊断

只读检查、证据收集、原因解释和建议。诊断不含修复授权，发现可修的问题说明结论，等用户要求。

## 内部子代理

由任一会话派出，接一个窄任务：限定范围的实现、测试、查证或审查。委派消息写明项目 AGENTS 完整路径、相关共享规程章节、当前票或输入、角色、可读可写范围、关键约束、预期结果、停止条件；子代理不继承派发者的聊天和规则。

子代理不替代一票一会话，不批准自身结果。派发者整合结果，对整票负责。

## 写回分工

- 每个文件一个写手，按总表的“写”列。决策台账的写手随决策现场变，交笔写进施工日志。
- 根路由由主控在新增核心资料或专题入口时更新；专题内新增票、Spec 由该票执行者更新专题索引。
- 两个会话要动同一个共享文件：主控指定一个写回者，另一个回传待更新项。

## 角色不明时

按开工包和施工日志核对；无法确认时保持只读并询问。角色称呼不带来写文件、发消息、部署或改配置的权限。
