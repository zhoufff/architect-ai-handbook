# 迁移指南：旧写法的决策卡改成决策卡写法

用于卡还是 decision-map 时期旧写法的项目：开头是 `Status:`、`Type:` 这类英文标签，正文有“已确认…”“补记”段。把卡改成共享规程 [03 的“决策卡写法”](../../协作规则/03-项目规则模板.md#decision-card)，出第一份决策简报。只换写法，决定内容不变。

- **谁做**：项目主控开一张迁移票，开工包用文末的模板；一个建图会话照本指南改卡、出简报。施工期决策现场在主控，派工时主控在施工日志把现场改为建图、范围写“旧卡迁移”，迁完改回（02 第 6 节）。
- **一次迁完**：生成器一次读全部卡，任一张不合写法就停，所以全部卡在同一张票里改完；中途用 `--check` 看还剩哪些。
- **用户在场一次**：按编号确认全部决定的标题。
- **旧的留着**：旧地图 HTML 和历史目录原样存档，不转换、不删；ADR 不改。迁完以后 decision-map 读不懂新写法，不再用它出图。

## 对照表

### 卡开头

| 旧写法 | 新写法 |
|---|---|
| `# 问题标题` | `# 决定：话题：结论句`，话题用旧标题里的名称（“照片存储查证”取“照片存储”），首屏按第一个“：”把一行分成话题和结论两栏；未定的写 `# 未定：问题一句`；查证完成的研究卡写 `# 决定：话题：查证结论一句` |
| `Type: decision` 或 `research` | 标签不留；`research` 的卡写成研究卡：“查证结论”代替“选择与理由”，“比较过的选项”写“无”；卡里有用户按选项作的选择的，见下一行 |
| `research` 的卡里有用户按选项作的选择 | 选择就是查证要回答的那道题的：整卡改成决策卡，“选择与理由”写用户的选择，查证结论并进它的理由，查证的比较表进“比较过的选项”；定于、谁定的、出处按决策卡填（用户选定那天、用户、选择的记录）；卡号和文件名不变，Spec、AGENTS 里指这张卡的引用照旧指对。查证覆盖几道题的：留研究卡，各项选择按“拆卡”拆成决策卡 |
| `Type: grilling` | 写成决策卡 |
| `Type: task` | 按内容判：含用户按选项作的选择的，写成决策卡，卡留在原目录，不移 `历史/`；不含的，列进待确认，由用户定写成研究卡、决策卡，还是移出决策卡目录归到票（留在目录里不改写，生成器会报错停下） |
| `Status`、`Decision` | `状态：`，对法见下表 |
| `Owner` | `谁定的：`，填法见“历史决定怎么填” |
| `Blocked by: none`，或 `01, 02` | `依赖：无`，或每行一张前置卡的名称加相对链接 |
| `Knowledge: assumed` | 假设了什么，写进“前提”表 |
| `Batch section` | 它指的那段就是这张卡的决定；标签不留 |
| `Knowledge` 的其他值、`Implementation`、`Assignee`、`Stage`、`Parent`、`更新` | 不留：进度归票和施工日志，改动时间看 Git |
| 旧写法没有的 | `定于`、`出处`、`取代`、`影响哪些卡`：填法见“历史决定怎么填” |

| 旧状态 | 新状态 |
|---|---|
| `Status: resolved` 且 `Decision: confirmed` | 已定 |
| 研究卡 `Status: resolved` | 已定（查证完成） |
| `Status: open` 或 `claimed`，或 `Decision: open` | 未定 |
| `Decision: withdrawn` | 否决 |
| `Decision: superseded` | 已被某卡取代：状态行链到取代它的卡，那张卡的“取代”写回本卡；查不到是哪张，列进待确认 |
| 其他组合 | 列进待确认，问用户 |

### 正文

| 旧写法 | 落到 |
|---|---|
| `## Question` | 问题 |
| `## 已知输入` | 背景并进“问题”，链接进“依据” |
| `## 已有证据…`、`## 有限核对…` | 决策卡：链接进“依据”。研究卡：结论进“查证结论”，链接进“依据” |
| 研究卡的 `## 本次适用范围`、`## 对本项目的含义` | 查证结论；牵动别的决定的，写进“影响” |
| `## 已确认…`、`## Answer`、`## 用户批准` | 一道选项题一项决定：几段是几道独立的选项题就拆几张，说同一项决定的几段合进一张；“独立”怎么算见“拆卡” |
| `明确选择：**“…”**`、`用户在第 N 轮选择：“…”` | “选择与理由”里逐字写“用户在第 N 轮选择：“…””；选项表里这一行的排除理由写“（选定）” |
| 批准段里写的理由 | 选择与理由；原记录没写理由的，写“理由未记录” |
| `未选的比较项：“甲”“乙”`，或下面逐条写“甲”：说明 | 选项表每项一行，说明里的好处、代价分到各格；没有的格写“未记录”；没写排除理由的，可以按代价归纳，以“按代价归纳：”开头 |
| `代价：…` | 影响 |
| `本卡取代 ADR NNNN “…”`、`本条取代 ADR NNNN …` | 影响里另起一整行“某项：“旧条文”（ADR NNNN） → 本次 → 新值”，本次写这一次怎么改（如“加小程序入口”）；ADR 链进“依据”；ADR 文件不改 |
| 一次改动改了几项（如 Spec 的两条） | 合成一整行，首屏 ③“改了哪些旧决定”才只出一行：“Spec 第 5、6 条：“旧条文甲”；“旧条文乙” → 本次 → 新值甲；新值乙” |
| 两张卡记着同一次改动（如一张定 Spec 换版，一张定换版里改的那一条） | 改动行只写在一张卡上：改的是哪一条约定，就写在定这一条的卡；另一张卡的“影响”写一句 `与[卡名](相对链接)是同一次改动，改动行记在那张卡`，这句不带“→”。两张都写，③ 会出两行说同一件事 |
| 含“前提”的句子 | 前提表一行：前提、谁负责满足、何时核实、不满足怎么办 |
| `## 还需补充`、`要展开`、`后续节点`、`后续处理`、`尚待后续` | 后续：只转仍待办的，谁＋做什么＋何时之前，一行一个；已做完的不转 |
| 已做完的“要展开的工作”，以及“谁来决定”“完成依据”这类只记经过的段 | 不另留，原文在 Git 历史和旧地图 HTML 里；其中写到谁拍板、原话在哪、证据链接的，按“历史决定怎么填”和“依据”取用 |
| `## 补记…` | 按内容分：另一项新决定，拆成新卡；改了本卡的决定，本卡只写现行决定，“定于”写改定那天，“出处”指改定的记录，旧值不另开卡，也不写成改动行；补充的证据、代价、后续，并进对应的段 |
| 正文里的“NN 卡”“某卡补记” | 指本项目的卡：改成卡名加相对链接，拆卡以后指到拆出的那张。指别的项目的卡：写明项目和卡名，不按编号链到本项目的卡 |
| 写成绝对路径的链接 | 改成相对链接；链到本机打不开的别的仓库，改成不带链接的纯文字路径 |
| 表里没有的段 | 按内容并进最接近的段；并不进去的原样留在卡末，生成器只在终端提示，简报不显示；只记经过的段按上面“不另留”那行 |

### 拆卡

- 一张卡里有几项独立的决定（原记录里是几道各自的选项题，且答的不是同一道题，见下条），就拆成几张：原卡留第一项和原文件名，拆出的卡用下一个空着的编号，起一个新的话题名；已有的卡不改编号，别处的链接照旧能用。
- “独立的选项题”指卡的问题之外的另一道题。答同一道题的细化、扩展、改定，哪怕当时是分开问的几道选项题，也合进原卡，只写现行决定：一张卡被问过十几道选项题、都在答卡的那道题，就不拆。
- 拆出的卡“依赖”写原卡；原来依赖原卡的卡，看依赖的是哪一项，改指相应的卡；拆卡不写“取代”。
- 不串历史：每张卡只写现行的决定；旧版本留在旧地图 HTML 和 Git 历史里，不为它另开被取代的卡。
- 卡号指针：Spec、AGENTS、专题索引这些迁移票只读的文件里，指的那一项已拆到新卡的“NN 卡”，迁移会话不改，逐条列进交回包，由项目主控同步。

### 历史决定怎么填

- **定于**：批准那天。取批准段标题里的日期，没有就用那一批所在轮次的日期。研究卡取查证完成那天：查证段写了日期就用它，没写就查 Git 里这张卡改成 `Status: resolved` 的那次提交。“更新”行的日期不算，它可能是后来改措辞的日子。几段合进一张的（补记改定、同一道题的细化扩展），取其中最近一次批准那天。查不到的列进待确认，编号确认时一并问；已定、否决的卡没有日期，生成器会报错停下。
  - 对以后各轮的影响：简报按“定于”划轮，一张卡只有一个日期。以后哪一轮再改定这张卡，整张卡都进那一轮的“本轮定了什么”，“影响”里以前各轮的改动行也跟着进 ③，看起来像这一轮又改了一次。首份简报不受影响，它列全部历史决定。
- **谁定的**：拍板的人。旧记录只写“用户决定”的，写项目 AGENTS 里的批准负责人，拿不准列进待确认。研究卡写做查证的会话或人；旧记录只写了“AI 查证”的，写查得到的会话名，查不到就写“AI 查证（会话未记录）”。
- **出处**：原话记在项目文件里（讨论记录、票的批准记录、Spec 变更记录），就链过去，写到第几条；原话只在对话里、旧卡的“明确选择”是唯一记录的，写“见本卡”，并在“选择与理由”里逐字留下所选的选项。研究卡写查证记录的链接，查证就写在本卡里的写“查证记录即本卡”。同一张卡批准过几次、原话分在卡里和票里的，写多行，一行一个出处，各加一句说明是哪次批准；续行不加列表符号，加了会原样显示。
- **取代**：旧状态是 `Decision: superseded` 的卡，在取代它的新卡上写回它，两边对上；拆卡不写；其余写“无”。
- **影响哪些卡**：写依赖本卡的卡，包括拆出的卡和按内容改指过来的卡；没有写“无”。漏写的，生成器会从别的卡的“依赖”反查补上并注明。

### 无、待确认、未记录

| 写法 | 什么时候用 | 例子 |
|---|---|---|
| 无 | 确实没有 | 取代、暂缓原因；没有前提；研究卡的比较过的选项 |
| 待确认 | 该有、原记录没有、要问用户；编号确认时一并问 | 前提表的谁负责满足、不满足怎么办；后续和下一步的何时之前 |
| 未记录 | 原记录没有，问不到也不改变决定 | 选项表的格；理由 |

## 步骤

1. **拿缺口清单。** 运行 `node <decision-brief 目录>/scripts/brief.mjs --check <项目根>`：只查不写，按文件列出缺的标签和段落。完成于：清单存进迁移票的记录，写明几张卡、几处缺口。
2. **定拆卡清单。** 逐张看批准段和补记，列出哪些卡拆、拆成什么、新编号、哪些依赖要改指，以及只读文件里指的那一项已拆到新卡的卡号指针（见“拆卡”末条）；对照时查不到的定于、谁定的、出处、取代对象，另列待确认清单。完成于：两份清单都在票的记录里。
3. **分批改卡。** 按对照表改，一批一个专题；派内部子代理分批改时按专题分，不让两个子代理改同一张卡。每批改完跑一次 `--check`。完成于：清单里只剩地图 MD，或已经没有问题。
4. **编号确认。** 在对话里用编号清单列出迁移后全部决定的标题，拆卡清单和待确认的事附在末尾，用户按编号确认。照答复改卡，把这份清单和用户的答复原样存进地图 MD 索引之后的批准段（02 第 6 节）。完成于：每一行都有用户按编号的确认，改动已写进卡。
5. **改地图 MD 头字段。** 标题下面先写五个标签（03“地图 MD 头字段”）：
   - 轮次接着旧地图的轮次往下数：旧地图出到第 11 轮，这份就是第 12 轮；日期写本轮确认那天。
   - 本轮范围写“旧卡迁到决策卡写法”；上一轮简报写“无”。
   - 旧的“当前下一步”并进“下一步：”，每条写成谁＋做什么＋何时之前，原来那段删掉。
   - 旧头部行（更新、Phase、Batch status、维护）生成器不读。要留就放在“上一轮简报：”那行之后、第一个二级标题之前；夹在“要用户决定”“下一步”中间，会被当成它们的条目印上首屏。大段的（如几十段维护记录）移到文末单独一节，免得把索引压到很下面。Batch decisions 只列卡号，由索引代替，删掉。
   - 一级标题：生成器去掉标题末尾的“决策地图”四个字，剩下的作项目名印在简报抬头和页面标题上；标题只有这四个字时用项目根的文件夹名。旧标题像“某项目重构规划与决策地图”，抬头会只剩“某项目重构规划与”，改成“某项目 决策地图”或只写项目名。
   - `## Decisions so far` 改成每个问题一行的索引（问题、依赖、状态、一句摘要加链接）；其他各节照留。

   完成于：`--check` 退出码 0。写法全都读得出以后它才开始查链接，这时报的坏链接按对照表最后一行改。
6. **出首份简报。** 照 [SKILL.md](SKILL.md) 第 2 步运行，输出 `项目总览/html/决策简报-第N轮-YYYYMMDD.html`。上一轮写“无”时，轮次日期以前定的都算本轮，“本轮定了什么”会列出全部历史决定，超过一屏是预期的；下一轮起只列新定的。完成于：文件已生成，路径、计数和提示交给用户。
7. **存档和交回。** 旧地图 HTML、历史目录留在原处，项目 AGENTS 里的登记照旧；交回包投给项目主控，列出只读文件里指的那一项已拆到新卡的卡号指针（文件、位置、旧卡号、改指哪张卡），由主控同步；试点记录抄送手册主控：改了几张、拆了几张、按无/待确认/未记录填了哪些、规则不够用的地方、简报计数与路径、首屏实测。完成于：两处都已送达。

## 示例

[`examples/迁移示例/`](examples/迁移示例/README.md) 是虚构的“物业报修小程序”，`改写前/`、`改写后/` 各是一个项目根。示例不用真实项目的卡；本指南里的判法来自作者两个真实项目的迁移试点：一个 12 张卡全部改写、拆出 2 张共 14 张，生成器第一次运行就通过；一个 22 张改写、拆出 8 张共 30 张，研究卡里的选择、拆卡粒度、同一次改动记两张卡等判法由它补进本指南。

| 改写前 | 改写后 | 演示的规则 |
|---|---|---|
| 报修入口一卡：一段“已确认”加一段“补记”，各是一道选项题 | 报修入口留第一项；补记拆成“夜间报修”，依赖报修入口 | 拆卡 |
| 报修入口的“本卡取代 ADR 0001 …” | 影响里一整行“报修渠道：… → 加小程序入口 → …” | 改 ADR 的改动行 |
| `Knowledge: assumed` 和补记里的“前提：” | 夜间报修的前提表，谁负责、不满足怎么办写待确认 | 前提、待确认 |
| 两项明确选择只在对话里 | 出处“见本卡”，选择与理由逐字留选项 | 出处 |
| 夜班派单 `Blocked by: 01`，依赖的是夜里那项 | 依赖改指夜间报修；出处链到讨论记录第 1 条 | 依赖改指、有记录指记录 |
| 未选的比较项只有名字 | 选项表缺的格写“未记录”，一格“按代价归纳：” | 选项表 |
| 照片存储查证：`Owner: AI 查证`，查证日期写在证据段标题里，“更新”行另有日期 | 定于取证据段的日期，谁定的“AI 查证（会话未记录）”，出处“查证记录即本卡”，写查证结论 | 研究卡 |
| 地图：更新、Phase、Batch 行，Decisions so far，当前下一步 | 五个标签在前，更新、维护行放在后面；索引；第 4 轮批准记录 | 地图 MD 头字段与旧行共存 |

在本目录跑：

```sh
node scripts/brief.mjs --check examples/迁移示例/改写前
node scripts/brief.mjs --check examples/迁移示例/改写后
```

第一条退出码 1，列出 4 个文件共 10 处；第二条退出码 0：第 4 轮，定了 3 项，改了旧决定 1 处，带前提 1 项，研究卡 1 张。要练生成，先把 `改写后/` 复制到同一个盘的别处，建好 `项目总览/html/` 再运行，免得在本目录多出文件。

## 迁移票开工包模板

项目主控派工时填好，由用户新开会话贴入。前八行是 [05](../../协作规则/05-任务开工包模板.md) 的核心，接着五行是建图变体，最后三行是迁移专用。

```text
任务：[项目]，把全部 [N] 张旧写法决策卡改成共享规程 03“决策卡写法”，出首份决策简报；决定内容不变
```
