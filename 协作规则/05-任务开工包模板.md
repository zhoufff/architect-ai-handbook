# 任务开工包模板

> 正式模板：2026-09-27（修订）。开工包是用户新开会话时贴入的第一条消息，由派工者填好。填了开工包不等于取得授权，硬停仍按 01。

## 填写

- `[方括号]` 全部换成已核实内容；不适用写“不适用＋理由”，核实不了写“待确认”并说明是否挡开工。
- 路径写接收会话能访问的完整路径。新会话不继承派工者的聊天和规则。
- 派工者填已知情况，执行者开工按 02 开工核对再复核。

## 简版：普通执行与问答

小改动在普通执行会话，五行：

```text
任务：在 [项目目录] 修改 [具体问题]，做到 [可检查的结果]。
入口：项目 AGENTS [路径]；施工日志 [路径]。
范围：只动 [范围]，不做 [排除项]；沿用 [现有约定]。
权限：本次允许 [具体改动]；涉及 [风险] 先报告。
交还：用 [验证方式] 检查，给结果和待我查看的入口，施工日志记一行。
```

只读一句：“请只读检查 [范围]，回答 [问题]，给证据和不确定项，不修改文件。”

内部子代理由派发会话按 04 交代，不用本模板。

## 核心：五种会话都填

```text
任务：[项目]，[本次目标，可验证的结果]
角色：[主控／建图／施工票执行者／审查／回归交付]，边界按 04
路线与关口：[02 的路线；本轮结束于哪个关口]
入口：项目 AGENTS [正文路径；多仓库时加本仓库入口 AGENTS 路径]；施工日志 [路径]；共享规程 [相关章节]
批准来源：[用户批准了什么、记录在哪；尚未批准的]
允许写：[文件或目录]；只读：[范围]；不做：[排除项]
需另行确认：[删除、数据、外部写入等本次相关的]
模型：期望按 01 的表；实测 [值或“未确认”]
交还：[交给谁；同机 Claude Code 写主控会话名，收工用交回包投递，否则贴给用户]；内容按 02 收工交还
```

## 变体：各会话多出来的

### 主控（项目首条消息）

```text
当前阶段：[探索期／施工准备／开发交付]；决策现场：[建图／主控]
接上一个主控：施工日志 [路径]；交接摘要 [路径或贴入；首个主控写“无”]
开工只读项目 AGENTS、施工日志、当前票；其余按路由在需要时读
你写记录不写产品：施工日志、根路由、开工包、AGENTS 偏好节；施工期的决策卡和 ADR；批准变更后的 Spec 和票
听到我的偏好、否决、第二次同样的问题，当场写进 AGENTS“偏好与不再问的事”
每次派工以“请新开会话，贴入以下开工包”结尾
会话间投递按 02 第 4 节：交回包和答复包由会话自己投，开工包和要我点头的事经我手
```

### 旧主控收尾（已有项目改按本规程前，贴给原主控）

```text
本项目将改按新的共享规程，这是你在旧规则下的最后一项工作。
在 [项目总览/md/施工日志.md，或现有状态文件路径] 写出施工日志六项：当前阶段、决策现场（探索期填建图，施工期填主控）、当前票、上一票验收结果、待我决定的事、下一步。
列出所有在途票和各自状态。给一份交接摘要：已批准的 Spec、票、决定各在哪，地图 MD 和决策卡在哪。
不改任何 Spec、票或决定，不搬文件。
```

### 主控（已有项目接入，贴给新开的主控）

```text
本项目此前按旧规则运行，现改按共享规程，见 02 已有项目接入。旧主控已交接：施工日志 [路径]；交接摘要 [路径或贴入]。
先读项目 AGENTS 和施工日志。按 03 对照根 AGENTS 补缺：登记施工日志、地图 MD、决策卡、ADR、HTML 输出的真实位置，路由表第一行指向施工日志，写手列按 04。现有文件留在原位。
决策现场：[建图／主控]。在途票：[列表和状态]，在原会话做完；之后的票用新开工包。
不改已批准的 Spec、票和决定，不迁移目录，不重跑规划。完成后报告对齐结果和待我确认的差异。
```

### 建图

```text
模式：[探索期，和用户定并记台账；施工期，只读 MD 出简报]
地图 MD：[路径]；决策卡目录：[路径]；本轮范围：[专题或这批问题]
简报输出：[路径]；Skill：[决策简报 decision-brief 的完整路径，在手册仓库 `工具/决策简报/SKILL.md`]
架构图：[不出写“无”；要出写“用 Archify”、图类型和输出文件（`项目总览/html/` 下，与现场写进卡“依据”的链接同名）]
交笔条件：[探索期填“地图上无未定问题挡住第一份 Spec”；施工期填“本轮简报完成”]
```

### 施工票执行者

```text
当前票：[路径]；Spec：[路径及相关验收条目]；ADR 与基线：[路径，不涉及则说明]
票序批准：[记录位置]；上一票验收与前置成果：[记录、版本和位置；首票写“无”]
现场：目录 [路径]；Git 根／分支或 worktree [已知值]；未提交改动 [已知情况]
验证：强度 [票中约定]；自动检查 [命令、目录、预期]；实际运行 [入口、操作、通过条件]；故障与恢复 [高风险时]
收工：三态之一；交验收单；Spec 或票有错交联系单；附审查开工包
```

### 审查

```text
票：[路径]；Spec：[路径]
比较范围：基线 [提交] → 待审 [提交或工作区]；未提交改动 [有／无]
两轴：Spec 轴、规范轴 [项目规范路径]
代码与 Spec 只读；问题清单写进本票审查记录一节，每条有位置、证据、严重程度；收工用交回包投给主控
```

### 回归交付

```text
Spec：[路径]；ADR：[路径]；全部票：[路径列表及验收记录]
目标环境：[真实环境和访问前提]
走通：[跨票的真实使用路径]
发布授权：[有／无；无则只交发布与恢复说明]
```

### 决策问答（用户直接开、自己填，只用这三行，不填核心）

```text
角色：决策问答，边界按 04。入口：项目 AGENTS [路径]；施工日志 [路径]；决策简报 [目录，读最新一轮]；地图 MD [路径]；决策卡 [目录]；ADR [目录]
只读：每条回答附出处，按卡的状态行说明（五值见 03）；不写文件、不批准施工、不派工
投回：我在问答中定下或改口的事，连同原话用交回包投给施工日志里写的当前决策现场 [同机会话名]
```

## 交回包与答复包

会话的最后一条消息，正文已在文件里；决策问答不写文件，写法见本节末。同机 Claude Code 会话自己投递，其他情况由用户贴。

交回包（子会话投给主控）：

```text
票：[路径]；会话：[本会话名]
状态：[完成待验收／部分完成／阻塞／审查完毕]
记录：[票的哪一节，或验收单、联系单、审查记录的路径]
待用户决定：[无，或一句话一条]
下一站：[主控验收／回票会话处理／等答复]
```

答复包（主控投回子会话，只限已批准范围内的答复）：

```text
票：[路径]；答复：[针对哪张联系单或哪个问题]
依据：[已批准的 Spec、票或票序条款]
答复：[一句话一条；不改变范围、不新增授权]
下一步：[继续／改后重交回包／等用户]
```

决策问答投给决策现场的交回包：票和记录写“无”；状态写“问答投回”；待用户决定逐条写用户原话和涉及的卡；下一站写“现场向用户复述确认后写卡”。
